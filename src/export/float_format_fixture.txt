# `float.ToString()` / `double.ToString()` under the invariant culture, captured from the runtime
#
# Produced by tools/probes/float-format, which calls the real
# `value.ToString(CultureInfo.InvariantCulture)` - the exact call `DefaultJsonWalker` reaches when it
# writes a float or double, because it passes no format string.
#
# Columns:
#   BOUNDARY|<kind>|<power of ten>|<text>          the fixed/scientific switch points
#   VALUE|<kind>|<IEEE bits as hex>|<text>         values chosen to separate the plausible rules
#
# Why this fixture exists: the port wrote these values with Rust's `Display`, and a comment claimed
# that `Display` "already gives the shortest round-trip form without an exponent for the magnitudes
# Unity stores". That claim is false, and the two formats disagree in three ways:
#
#   1. EXPONENT THRESHOLD. Rust's `Display` never uses exponent notation; .NET switches to it for
#      exponent < -5 or exponent >= 9 (float) / >= 17 (double). So 1e-5f prints `1E-05`, not
#      `0.00001`, and 1e9f prints `1E+09` while 1e8f still prints `100000000`.
#   2. EXPONENT SPELLING. .NET writes `E+09`, `E-05`, `E+38` - uppercase E, an explicit sign for
#      positive exponents, and at least two exponent digits. Rust's `{}` never produces this form
#      at all.
#   3. NON-FINITE VALUES. .NET writes bare `NaN`, `Infinity` and `-Infinity` (which is not valid
#      JSON, but is what the reference emits), while Rust's `Display` writes `NaN`, `inf` and
#      `-inf`.
#
# Both kinds also print integral values without a trailing `.0` (`1`, not `1.0`) and preserve the
# sign of negative zero (`-0`).
# BOUNDARY|f32|1e-6|1E-06
#
# Tie rows: Rust's shortest form can pick a different same-length decimal than .NET, which
# resolves the tie toward the even last digit. -280.890625f32 is -280.89062 under .NET and
# -280.89063 under Rust's Display, and the JSON walker must print the .NET spelling.
