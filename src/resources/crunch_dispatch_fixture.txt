# Crunch decode dispatch: reference-runtime evidence
#
# Captured from the frozen reference's own conversion assemblies by
#   dotnet run --project tools/probes/crunch-faces/CrunchFacesProbe.csproj -c Release -- <refroot> <fixtureDir>
# which loads `AssetRipper.Conversions.Crunch.dll` and `AssetRipper.Conversions.UnityCrunch.dll` out
# of the isolated baseline build and calls the shipped `TryDecompress` entry point on every
# committed CRN fixture, through BOTH decoders.
#
# Columns:
#   OUT|<decoder>|<fixture>|ok|<byteLength>|<sha256[:16]>
#   OUT|<decoder>|<fixture>|<failed>              the entry point returned false
#   OUT|<decoder>|<fixture>|<threw ExceptionType> the entry point crashed
#
# Why both decoders are run over every fixture: `CrunchHandler.IsUseUnityCrunch` claims the source
# version alone decides for 2017.3+, and that the *format* decides for older versions. Running the
# wrong decoder over a fixture shows what that gate is actually protecting against, rather than
# merely asserting that the gate exists.
#
# Reading the rows:
#   * `unity_etc1.crn` through the classic decoder THROWS a NullReferenceException, and
#     `unity_etc2a.crn` through the classic decoder explicitly FAILS. So an ETC-crunched payload
#     cannot be handled by the classic path at all - the format branch is load-bearing, not
#     cosmetic.
#   * `classic_dxt1.crn` and `classic_dxt5.crn` decode through BOTH decoders but to different
#     bytes, so the version branch changes the *pixels*, not just success or failure. Choosing the
#     wrong side here would be a silent wrong-image bug rather than an error.
#   * The three `unity_*` fixtures all decode through the Unity decoder, matching the port's gate:
#     formats 64/65 select UnityCrunch on any version, and 2017.3+ selects it unconditionally.
#   * `multi_face_multimip.crn` is an 8x8 six-face DXT1 cubemap with three mip levels. The classic
#     decoder returns all 288 DXT bytes; UnityCrunch throws, so the pre-2017.3 DXT dispatch is also
#     load-bearing for cubemaps.
#
# The port's own 64-bit RGBA oracle hashes are pinned separately in
# `src/resources/texture_converter.rs`; these rows are the reference-runtime cross-check that the
# dispatch itself is right.
